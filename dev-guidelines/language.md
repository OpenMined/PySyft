# Language

These rules apply to everything we write about the code: answers, PR descriptions, reviews and
docs.

- Use simple language.
- Use the terms the code already uses. Do not invent your own concepts.
- Most important: do not assume the reader has context.
- When you explain a change to the code, say when the changed code runs and what it did before:
  "When we do X, we previously did Y. Now we do Z."
- Name what you refer to, also when it is something you said earlier.
